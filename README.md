# Name That LLM

Our entry for the Kaggle competition [Name That LLM](https://www.kaggle.com/competitions/name-that-llm):
given a short passage (40–250 words), predict which of 18 language models wrote it. The metric is
balanced accuracy.

This is a project for the Workshop in Machine Learning and Data Analysis (0368-3548) at Tel Aviv
University, Fall 2026–27. The schedule and roles are in [PLAN.md](PLAN.md); the proposal is in
[docs/](docs/).

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Download the competition files from the
[Data page](https://www.kaggle.com/competitions/name-that-llm/data) (you must accept the
competition rules first) and put `train.csv` and `test.csv` in `data/`. The data is not committed.

## Run

```bash
python -m pytest tests                              # checks the pipeline on synthetic data
python -m src.train --model tfidf_style_blend --owner <your name>
```

`src.train` cross-validates one model from `src/models/__init__.py`. It prints balanced accuracy per
fold, saves out-of-fold probabilities to `oof/`, and appends rows to `experiments.csv`.

## Method so far

1. **TF-IDF model.** Word and character n-gram counts into logistic regression.
2. **Style model.** 48 hand-made features (sentence lengths, punctuation rates, formatting) into
   logistic regression.
3. **Blend.** The two models' log-probabilities are added, with the style model at half weight.
4. **One model per prompt.** In `train.csv` no prompt has two passages from the same model. We
   group the test passages by topic to recover the prompts, then choose the labelling of each group
   in which no model repeats (`src/prompts.py`). This assumes the hidden test set is built like the
   training set. The leaderboard says it is not: this step added nothing there (0.355 with it,
   0.356 without), most likely because the test set has few passages per prompt.
5. **Fine-tuned DeBERTa.** The pretrained `microsoft/deberta-v3-base` encoder with one linear layer
   on top, all weights trained for 6 epochs (`src/models/transformer.py`). Added to the blend at
   half weight.
6. **Features from a frozen language model.** Each passage is run through Qwen 3 4B without
   training it; the hidden vectors of an early layer, averaged over the passage, go into logistic
   regression (`src/features/llm.py`). The features were extracted on Kaggle's GPU by
   `notebooks/experiment_llm_features.ipynb`. Added to the blend at half weight.

7. **More training data.** The public open pool
   ([crtproduction/name-that-llm-open-pool](https://www.kaggle.com/datasets/crtproduction/name-that-llm-open-pool),
   CC BY-SA 4.0) has about 226,000 extra passages generated by other participants from the same 18
   models; the competition rules allow public external data. TF-IDF trained on up to 8,000 pool
   passages per model, with no passage from `train.csv`, scores 0.485 on `train.csv`, against 0.344
   for TF-IDF trained on `train.csv` itself (`src/pool.py`, `src/pool_experiment.py`). The pool's
   labels are its sources' claims and were not re-verified.

## Submit

Kaggle runs submissions with internet off, so each submission notebook carries a copy of the code
it needs. The notebooks are generated from `src/`; never edit them by hand.

```bash
python -m src.build_notebook                        # rewrites the notebooks in notebooks/
```

| Notebook | What it submits |
|---|---|
| `submission_tfidf_logreg.ipynb` | TF-IDF model |
| `submission_blend.ipynb` | Blend |
| `submission_blend_assign.ipynb` | Blend with one model per prompt |
| `submission_pool_blend.ipynb` | All four models, TF-IDF trained on the open pool too. Needs a GPU session, `deberta-v3-base`, Qwen 3 4B and the open pool dataset attached |
| `submission_pool_deberta_blend.ipynb` | TF-IDF and DeBERTa trained on the open pool, plus style and Qwen features. Needs a GPU session, Qwen 3 4B, the open pool dataset and the output of `ntl-train-deberta-pool` attached |
| `submission_pool_two_deberta_blend.ipynb` | As above with both the longer and the big pool DeBERTa. Needs a GPU session, Qwen 3 4B, the open pool dataset and the outputs of `ntl-train-deberta-pool-long` and `ntl-train-deberta-pool-big` attached |
| `submission_pool_qwen_lora_blend.ipynb` | As above plus the LoRA-tuned Qwen. Also needs the output of `ntl-train-qwen-lora-pool` attached |
| `submission_pool_qwen_lora_light_blend.ipynb` | The 0.581 blend plus the LoRA-tuned Qwen at weight 0.5. Same inputs as the row above |
| `submission_pool_glm_blend.ipynb` | The 0.581 blend, then GLM likelihood on the 30% of test passages it finds most GLM-like. Needs GPU T4 x2 and, besides the 0.581 blend's inputs, the outputs of `ntl-train-glm-likelihood` and `estopadilla/ntl-glm-likelihood-train` and the three GLM segment datasets |
| `submission_qwen_lora.ipynb` | The LoRA-tuned Qwen alone, to check it on the test prompts. Needs a GPU session, Qwen 3 4B and the output of `ntl-train-qwen-lora-pool` attached |
| `submission_full_blend.ipynb` | All four models. Needs a GPU session, `deberta-v3-base` and Qwen 3 4B attached |
| `submission_deberta_blend.ipynb` | Blend with fine-tuned DeBERTa. Needs a GPU session and `deberta-v3-base` attached as an input |

Upload a notebook to the competition on Kaggle, attach the competition data, keep internet off,
save a version and submit it.

`train_deberta_pool.ipynb` is not a submission: it fine-tunes DeBERTa-v3-base on about 70,000
open-pool passages (GPU, `deberta-v3-base` and the open pool attached), scores it on all of
`train.csv`, and saves the model as notebook output for later submissions to load.
`train_deberta_pool_long.ipynb` does the same with up to 8,000 passages per model (about 136,000)
and 3 epochs, about 2.5 hours. `train_deberta_pool_big.ipynb` uses up to 12,000 per model (about
192,000), with the loss weighted so the two models with under 5,000 pool passages count as much as
the rest; about 3.2 hours. `train_qwen_lora_pool.ipynb` fine-tunes the first 18 layers of Qwen 3 4B
with LoRA (rank 16 on every linear layer, written in `src/models/transformer.py`) on about 71,500
pool passages in 3.7 hours; it needs Qwen 3 4B and the open pool attached and saves only the LoRA
weights, which a submission loads on top of the attached Qwen 3 4B. A submission notebook loads
each trained model by the name of its output folder, loads it only while it predicts, and stops if
one it needs is missing.

`train_glm_likelihood.ipynb` scores every `train.csv` passage under two of the 18 models
themselves, GLM-5.3-Flash and GLM-5.3, and cross-validates a classifier on the result
(`src/features/glm.py`, `src/glm_experiment.py`). A model gives its own text higher probability,
and the two GLM labels are our weakest (recall 0.20 and 0.37). The open weights (118 GB for Flash
alone) do not fit on Kaggle's GPUs, so they run one layer segment at a time with José Padilla's
`ntl-segrun`, a patched llama.cpp (see Credits). It needs GPU T4 x2 and, attached, the output of
his notebook and the three segment datasets; about an hour.

`train_family_specialists.ipynb` trains, for each maker (GPT, Gemini, Claude), a DeBERTa and TF-IDF and
style models on open-pool passages of that maker's models only (`src/family_experiment.py`). Most of
the GLM blend's errors are within a family: on `train.csv` it splits a GPT passage among the five GPT
models correctly 0.649 of the time, and if it always did, the blend would score 0.717 instead of
0.626. `src/models/family_model.py` keeps the blend's total for the family and re-splits it with the
specialist's opinion. GPU, `deberta-v3-base` and the open pool attached; it saves the DeBERTas.

`python -m src.predict --model tfidf_style_blend --assign` does the
same locally.

## Validation

Every experiment uses the same 5 folds from `src.data.make_folds`. All passages that answer one
prompt stay in one fold, because the hidden test set uses prompts that are not in the training set.
Scores are reported as mean ± std of balanced accuracy across folds.

## Layout

```
src/
  data.py                 labels, loading, folds
  evaluate.py             balanced accuracy, model and lab confusion tables
  features/tfidf.py       word and character n-gram features
  features/stylometry.py  hand-made style features
  models/linear.py        logistic regression on TF-IDF and on style features
  models/blend.py         adds the log-probabilities of several models
  models/__init__.py      the list of models by name
  prompts.py              groups passages by prompt; one model per prompt
  train.py                cross-validation entry point
  predict.py              fit on all data, write submission.parquet
  build_notebook.py       generates the Kaggle submission notebooks
tests/                    pipeline tests on synthetic data
notebooks/                the generated Kaggle submission notebooks
configs/                  one file per experiment (to come)
docs/                     proposal
experiments.csv           one row per experiment
```
